# 基于多设计模式下的同步&异步日志系统
## 项目目标
本项目要实现一个日志系统，支持多级别日志消息、同步和异步日志，支持可靠写入控制台、支持多线程并发写日志

## 开发环境
Ubutun vscode g++ Makefile

## 核心技术
类层次设计 C++11（多线程、智能指针、右值引用）

## 日志系统介绍

### 同步写日志
输出日志时，必须等待日志输出语句执行完毕后，才能执行后面的业务逻辑语句，日志输出语句与程序的业务逻辑语句在同一个线程运行，每次调用一次打印日志API就对应一次系统调用write写日志文件

在高并发场景下，若日志数量不断增加，大量的日志陷入等量的write系统调用，有一定的系统开销;同时打印日志的进程附带了大量同步的磁盘IO,影响程序性能。

### 异步写日志
异步写日志指的是日志输出语句与业务逻辑语句并不是在同一个线程中运行，而是有专门的线程用于进行日志输出操作，业务线程只需要将日志放到一个内存缓冲区中不用等待即可继续执行后续业务逻辑（作为生产者），而日志的落地操作交给单独的日志线程去完成（作为消费者）。

## 作用
1.日志写入指定位置（标准输出，指定文件，滚动文件）日志系统需要支持将日志消息落地到不同的位置————多落地方向。

2.日志写入指定位置，支持同步和异步的方式

3.日志输出以日志器为单位，支持多日志器（不同的项目组有不同的输出策略）

## 模块划分
1.日志等级模块：将日志分为多少个等级，不同的日志有对应不同的等级，以便于控制输出。

2.日志消息模块：封装一条日志所需要的各种要素（时间，线程ID,文件名，行号，日志等级，消息主体）。

3.消息格式化模块：按照指定的格式，对日志消息关键要素进行组织，最终得到一个指定格式的字符串。

4.日志落地模块：负责对日志消息进行指定方向的写入输出。

5.日志器模块：对以上几个模块的整合，包括日志限制输出等级，消息格式化模块对象，日志落地模块对象、同步日志器模块、异步日志器模块。

6.异步线程模块：负责异步日志的实际落地输出功能。

7.单例日志器管理模块：对日志进行全局管理，以便于能够在项目的任何位置获取指定的日志器进行日志输出。

### 日志等级模块
1.定义日志系统所包含的所有日志等级，从低到高包括：
UNKNOWN=0,DEBUG 调试等级日志，INFO 提示等级日志，WARNING 警告等级日志，ERROR 错误等级的日志，FATAL 致命错误等级的日志，OFF 关闭日志。
项目中都会设置一个默认的日志输出等级，只有输出的日志等级大于等于默认的，才会进行输出。
2.提供一个接口，将对应等级的枚举，转换成一个对应的字符串 DEBUG-> "DEBUG"
